# Lead prioritization: ICP fit, product usage, PQL vs SQL

## Description
How to prioritize leads and customers when resources are limited: define ICP, use a 2×2 fit×usage matrix, and operationalize PQL/SQL so you spend human time where it converts.

## Main sections
### ICP (ideal customer profile) as a sales filter
ICP describes the *company/account* that gets the most value and is most likely to succeed.

Common ICP dimensions:
- industry
- company size / revenue
- geo
- tech stack (technographics)
- buying process
- key pains you solve

### Fit × usage matrix (2×2)
Segment by:
- **Fit**: how close to ICP
- **Usage**: how much value signals appear (product engagement)

Quadrants and actions:
1. **High fit / high usage**: assign humans, upsell/expand, ask for case studies.
2. **High fit / low usage**: automate education + activation; intervene when signals rise.
3. **Low fit / high usage**: support reasonably; explore as potential new ICP.
4. **Low fit / low usage**: lowest priority; consider churn-prevention only if cheap.

### PQL vs SQL (practical definitions)
- **PQL (Product Qualified Lead)**:
  - user demonstrates value through usage (trial/freemium signals)
  - prioritize when usage crosses thresholds
- **SQL (Sales Qualified Lead)**:
  - sales verifies ICP fit + intent + next step

### What to track to prioritize well
For B2B SaaS:
- activation milestones
- repeated usage events
- number of teammates invited
- “aha moment” completion
- inbound intent (pricing page visits, replies, demo requests)

## Practical examples
### Example 1 — prioritization rule
If a lead is high fit AND:
- invited ≥ 2 teammates, OR
- used key feature ≥ 3 times in 7 days,
then treat as PQL → convert to SQL with human outreach.
