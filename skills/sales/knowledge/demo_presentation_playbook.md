# Demo presentation playbook (Problem → Solution → Action)

## Description
How to run product demos that convert: activate the problem, show one main feature that solves it, support with proof, and end with a clear next step. Includes Tell/Show/Tell and a copy-paste opening script.

## Main sections
### The #1 mistake: demoing everything
Founders often over-demo features. Buyers want:
- proof you solve *their* problem,
- clarity on next steps,
not a UI tour.

### Tell / Show / Tell (simple structure)
1. **Tell**: what you will show and why it matters
2. **Show**: the product in action (focused)
3. **Tell**: recap the value the buyer just saw

### PSA demo spine (Problem → Solution → Action)
Default 30-minute structure:
- **Problem (5 min)**: agree on the pain and cost
- **Solution (15 min)**: show **one** main feature
- **Support (7 min)**: only features that strengthen the main solution
- **Action (3 min)**: next step with date/time

### “Problem slide” checklist
A good first slide:
- states the problem in ICP language
- quantifies losses (time/money/risk)
- includes emotional consequence (stress/burnout) *when relevant*
- states what happens if not solved

### Demo opening script (copy/paste)
“Hi, {Name}. Before we start — remind me, what’s the main problem we must solve today?

{listen}

Great. Then I’ll show you the one workflow that fixes exactly that. After that, we’ll look at a couple of supporting parts, and we’ll finish with the next step. Sound good?”

### Interaction rules
- Ask a question at least every ~5 minutes (avoid monologue).
- Translate features into outcomes (A→C).
- End with a concrete CTA (pilot, second call with stakeholders, offer).

Outcome: “no manual uploading; saves 30–45 minutes per hiring cycle.”
