# MVP approaches and DVF (Desirable, Viable, Feasible)

## Description
How to choose an MVP approach that you can actually deliver with your resources. Uses the DVF framework and five MVP implementation approaches from manual service to minimal code.

## Main sections
### DVF framework (IDEO)
Before you build, check the triangle:

- **Desirable**: do users want it? does it solve a real pain?
- **Viable**: can it be a real business? (pricing, CAC, market size)
- **Feasible**: can you deliver it with your current time, skills, budget, constraints?

MVP failure pattern:
- promise is “desirable” and maybe “viable”, but not “feasible” for your team.

### Five MVP approaches (from lowest to highest engineering)
1. **Concierge / productized service**
   - deliver outcomes manually and openly
   - best for high-ticket B2B and fast learning

2. **Wizard-of-Oz**
   - user thinks it’s automated
   - team performs key steps manually behind the scenes
   - use carefully to avoid wrong expectations

3. **Visual prototype**
   - UI mock/prototype + demo video
   - great for pre-selling, interviews, early feedback

4. **Minimal code**
   - build only the core promise + basic auth + minimal UI
   - avoid architecture overkill

5. **Full product**
   - only after learning confirms value and feasibility

### Choosing the approach (rules of thumb)
Pick the lowest-tech approach that still tests the core assumption:
- If trust and workflow matter: concierge first.
- If UX concept matters: prototype first.
- If core is technical and must be real: minimal code.

### Practical “build order” for minimal code MVP
1. define the single core workflow
2. build the workflow end-to-end
3. add auth (if needed)
4. add payments (only if needed for learning)
5. test with real users
