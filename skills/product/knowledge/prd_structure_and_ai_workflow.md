# PRD structure and AI-assisted workflow (2025)

## Description
A modern PRD structure and a practical process for writing PRDs faster with AI while keeping human accountability for critical decisions.

## Main sections
### What a PRD is for
A PRD answers:
- what to build
- for whom
- why it matters
- what “success” means

### PRD sections (modern default)
1. **Title + metadata**
   - owner(s), date, status, links
2. **Problem definition**
   - who has the problem, proof, why alternatives fail
3. **Goals**
   - one output goal
   - 2–3 input metrics
   - non-goals
   - guardrails
4. **Solution**
   - high-level approach
   - user stories
   - priorities (P0/P1/P2)
   - milestones
5. **Launch plan**
   - rollout strategy
   - success criteria
   - test/iteration plan
6. **Technical requirements**
   - integrations
   - performance
   - security/compliance
7. **Design / UX**
   - key flows
   - prototype links

### Step-by-step PRD creation process
1. Collect inputs
   - user interviews
   - competitor analysis
   - problem sizing
   - technical constraints
2. Draft PRD
   - start with problem + goals
   - add requirements with acceptance criteria
3. Collaborate + iterate
   - review with engineering and stakeholders
4. Approve + operationalize
   - keep PRD updated as a living doc

### Using AI (responsibly)
AI is great at:
- structuring messy inputs
- generating a first draft
- suggesting missing sections

AI is weak at:
- business context
- feasibility assessment without constraints

Best practice:
- feed AI a “product manifesto” (ICP + problem + value + constraints)
- then review and correct, especially constraints and metrics
